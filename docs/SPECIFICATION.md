## 1. Описание продукта

### 1.1 Назначение

Веб-приложение для планирования отделки и расстановки мебели в типовом доме под ключ. Встраивается на сайт строительной компании. Конечный пользователь — заказчик, получивший дом в черновой отделке. Приложение помогает ему составить план действий и предварительную смету по доведению дома до состояния «готов к заселению».

### 1.2 Целевая аудитория

- **Конечный пользователь:** клиент строительной компании, не дизайнер, без опыта работы с CAD.
- **Покупатель приложения:** строительная компания, продающая дома под ключ. Встраивает виджет на свой сайт (Tilda / WordPress / кастомный HTML).

### 1.3 Ключевые требования

- Полное соответствие 2D-схемы и 3D-сцены: цвета, габариты, расположение объектов.
- Возможность последовательно проходить 4 этапа и возвращаться к предыдущим.
- Универсальное встраивание на любой сайт через `<iframe>`.
- Локальное сохранение проектов и экспорт сметы в PDF/PNG.
- Защита от типовых веб-эксплоитов (XSS, CSRF, clickjacking).
- Покрытие тестами всех 4 этапов работы пользователя.

## 3. Архитектура

### 3.1 Модель встраивания

Приложение хостится на одном домене (`designer.your-domain.com`) и встраивается на сайт клиента одной строкой:

```html
<iframe
  src="https://designer.your-domain.com/?clientId=CLIENT_ID"
  width="100%"
  height="800"
  style="border: none;"
  allowfullscreen
></iframe>
```

URL-параметры:

- `clientId` (обязательный) — идентификатор покупателя приложения, определяет прайс и брендинг.
- `projectId` (опционально) — для загрузки сохранённого проекта.
- `lang` (опционально, default `ru`) — язык интерфейса.

**Безопасность iframe:**

- `Content-Security-Policy: frame-ancestors *` (по умолчанию для коммерческой модели) или whitelist по доменам клиентов.
- `X-Frame-Options` НЕ устанавливается (несовместим с frame-ancestors).
- Никаких чувствительных данных в URL — только публичные идентификаторы.

### 3.2 Единая модель данных проекта

Главный принцип архитектуры: **один Zustand-стор хранит весь проект, 2D и 3D — это два рендеринга одних и тех же данных**.

```typescript
type Project = {
  version: '1.0';
  clientId: string;
  projectId: string; // UUID, генерится при создании
  layoutId: 1 | 2 | 3; // одна из трёх типовых планировок
  createdAt: string;
  updatedAt: string;
  currentStage: 1 | 2 | 3 | 4; // текущий этап

  // Заполняется из layout JSON при выборе планировки
  rooms: Room[];
  walls: Wall[];
  electricalPanel: { x: number; y: number }; // позиция щитка в тайлах

  // Этап 2: черновая отделка
  flooring: Record<RoomId, 'screed' | 'screed_heated'>; // по умолчанию screed
  ceiling: Record<RoomId, 'stretch' | 'drywall'>; // по умолчанию stretch
  electricalPoints: ElectricalPoint[]; // выбранные пользователем
  electricalRoutes: ElectricalRoute[]; // вычисленные пути

  // Этап 3: чистовая отделка
  floorCovering: Record<RoomId, 'linoleum' | 'laminate' | 'tile' | 'quartz_vinyl'>;
  wallCovering: Record<WallSegmentId, 'wallpaper' | 'paint'>; // по сегменту стены, не по комнате
  furniture: FurnitureInstance[];
};

type Room = {
  id: RoomId;
  // Уточнено в v1.0.0: добавлены 'corridor', 'wardrobe' (по реальным планам Таи).
  // 'veranda' — отдельный объект (не входит в rooms, только для отображения).
  type: 'bathroom' | 'kitchen' | 'boiler' | 'living' | 'bedroom' | 'corridor' | 'wardrobe';
  name: string; // RU-название для UI
  tiles: TileCoord[]; // тайлы, входящие в комнату
  area: number; // м², считается из tiles
};

type Wall = {
  id: WallSegmentId;
  type: 'external' | 'internal';
  start: TileCoord;
  end: TileCoord;
  adjacentRooms: RoomId[]; // для external — один, для internal — два
};

type ElectricalPoint = {
  id: string;
  wallId: WallSegmentId;
  position: number; // 0..1 — позиция вдоль стены
  type: 'socket' | 'switch';
};

type ElectricalRoute = {
  pointId: string;
  path: TileCoord[]; // тайлы потолка от щитка/ответвления до точки
};

type FurnitureInstance = {
  id: string; // UUID
  catalogId: string; // ссылка на furniture-catalog.json
  position: TileCoord; // координата левого нижнего угла
  rotation: 0 | 90 | 180 | 270; // градусы
  mirrored: boolean;
};

type TileCoord = { x: number; y: number }; // целые числа, тайлы

// Расширение для v1.5.0 — окна и дверные проёмы
type Window = {
  id: string;
  wallId: WallSegmentId;
  position: number; // 0..1 — позиция вдоль стены (центр окна)
  width_tiles: number; // ширина в тайлах (целое, default 6 = 1.5 м)
  sill_height_m: number; // высота от пола до низа окна (default 0.9)
  height_m: number; // высота окна (default 1.5)
};

type Door = {
  id: string;
  wallId: WallSegmentId;
  position: number; // 0..1 — позиция центра проёма вдоль стены
  width_tiles: number; // ширина проёма в тайлах (default 3 = 0.75 м)
  height_m: number; // высота проёма (default 2.1)
  hinge: 'left' | 'right'; // сторона петель — для дуги в 2D
  swing: 'inward' | 'outward'; // направление открытия — для дуги в 2D
};

// Расширение Layout JSON: дополнительные поля
// {
//   ...existing fields...,
//   windows: Window[],
//   doors: Door[]
// }
```

### 3.3 Тайловая система

- **Размер тайла:** 0.25 м × 0.25 м
- **Начало координат:** левый нижний угол схемы, ось Y направлена вверх (как в математике, не как в экране)
- **Все размеры округлены до тайла:** мебель, стены, точки на стенах
- **Преобразование в 3D:** `world_x = tile_x * 0.25`, `world_z = tile_y * 0.25` (Y в Three.js — вверх)

## 4. Функциональные требования

### 4.1 Этап 1 — Выбор планировки

| ID   | Требование                                                                                                                       |
| ---- | -------------------------------------------------------------------------------------------------------------------------------- |
| F1.1 | Пользователю показываются 3 типовые планировки в виде превью (миниатюры 2D-схем).                                                |
| F1.2 | Каждая планировка имеет название, общую площадь, перечень комнат.                                                                |
| F1.3 | Выбор планировки загружает её данные (rooms, walls, electricalPanel) в стор.                                                     |
| F1.4 | После выбора пользователь видит выбранную планировку на полном экране 2D-вида.                                                   |
| F1.5 | На схеме отображены: внешние стены, межкомнатные стены, заливка зон комнат цветами из `PALETTE.rooms`, иконка электрощитка.      |
| F1.6 | Кнопка «Далее» переводит на этап 2.                                                                                              |
| F1.7 | Смена планировки на этапе 1 после уже сделанной работы на 2/3/4 показывает confirm-диалог («Все ваши изменения будут сброшены»). |

### 4.2 Этап 2 — Черновая отделка

#### 4.2.1 Стяжка пола

| ID     | Требование                                                                                      |
| ------ | ----------------------------------------------------------------------------------------------- |
| F2.1.1 | Для каждой комнаты пользователь выбирает: `screed` (по умолчанию) или `screed_heated`.          |
| F2.1.2 | UI: список комнат сбоку, у каждой — два радио-чекбокса.                                         |
| F2.1.3 | На 2D-схеме комнаты с тёплым полом подсвечиваются (например, рамкой `PALETTE.electrical.wire`). |

#### 4.2.2 Электрика

| ID     | Требование                                                                                                                                                                                                                                                  |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F2.2.1 | Пользователь видит позицию электрощитка (иконка).                                                                                                                                                                                                           |
| F2.2.2 | Клик по тайлу, прилегающему к стене (с внутренней стороны), создаёт электроточку.                                                                                                                                                                           |
| F2.2.3 | Точка может быть `socket` или `switch` — переключатель в UI.                                                                                                                                                                                                |
| F2.2.4 | После создания точки автоматически вычисляется маршрут провода: BFS по тайлам потолка от щитка ИЛИ от ближайшей точки на уже существующем дереве проводки до новой точки. Маршрут — кратчайший по Манхэттенской метрике, движение только по 4 направлениям. |
| F2.2.5 | Маршрут отрисовывается на 2D-схеме линиями цвета `PALETTE.electrical.wire`.                                                                                                                                                                                 |
| F2.2.6 | В 3D-сцене провод — цилиндр диаметром 0.02 м того же цвета, идёт по потолку (Y = высота комнаты, по умолчанию 2.7 м).                                                                                                                                       |
| F2.2.7 | Удаление точки: пересчитывается всё дерево маршрутов.                                                                                                                                                                                                       |
| F2.2.8 | **Уточнено в v1.0.0:** Точки можно ставить на любой внутренней или внешней стене (точка остаётся внутри дома, на тайле у стены). Изначальное ограничение про «нельзя на внешних стенах» снято по запросу заказчика.                                         |

#### 4.2.3 Штукатурка

| ID     | Требование                                                                               |
| ------ | ---------------------------------------------------------------------------------------- |
| F2.3.1 | Применяется автоматически ко всем стенам, выбора у пользователя нет.                     |
| F2.3.2 | На 2D отображается информационная плашка: «Штукатурка стен — выполняется автоматически». |

### 4.10 Багфиксы и улучшения экспорта (v1.1.0)

## 5. Нефункциональные требования

### 5.1 Производительность

- Стартовая загрузка приложения: < 3 с на 4G.
- 2D-канвас должен поддерживать 60 FPS при ≤ 200 элементах.
- 3D-сцена: 30 FPS на интегрированной графике для типового дома (~60 м²).

### 5.2 Совместимость

- Браузеры: Chrome, Firefox, Safari, Edge — последние 2 мажорные версии.
- Минимальный десктоп. Mobile-поддержка — out of scope для ВКР, но в коде не делать допущений, ломающих мобайл.

### 5.3 Безопасность

| Угроза                                   | Мера                                                                                                                                            |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| XSS через пользовательский ввод          | DOMPurify на всех текстовых полях; строгая типизация; React по умолчанию экранирует                                                             |
| Code injection через импорт JSON-проекта | Zod-валидация схемы; запрет любых полей, не описанных в типе                                                                                    |
| Clickjacking                             | `Content-Security-Policy: frame-ancestors` whitelist; для коммерческой модели — конфигурируется per clientId                                    |
| CSRF                                     | Не релевантно (нет state-changing API на стороне сервера в MVP)                                                                                 |
| Information disclosure через URL         | Никаких токенов в URL, только публичные ID                                                                                                      |
| Supply chain                             | `npm audit` в CI, Dependabot включён                                                                                                            |
| CSP                                      | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self' https://*.supabase.co` |
| LocalStorage poisoning                   | Валидация при чтении, fallback на чистый стейт при ошибке парсинга                                                                              |

### 5.4 Доступность (a11y) — minimal viable

- Все интерактивные элементы доступны с клавиатуры.
- ARIA-метки на иконочных кнопках.
- Контраст текста ≥ 4.5:1.

## 7. Git Workflow

### 7.1 Ветки

- `main` — защищённая, только через PR с зелёным CI и approve.
- `develop` — текущая интеграционная (опционально, можно работать напрямую с `main` через feature-branches).
- `feature/<scope>-<short-name>` — новая фича. Пример: `feature/stage2-electrical-routing`.
- `fix/<short-name>` — багфикс.
- `chore/<short-name>` — инфраструктура, зависимости.

### 7.2 Commits

- Conventional Commits: `feat: …`, `fix: …`, `chore: …`, `docs: …`, `test: …`, `refactor: …`.
- Английский язык.
- Тело коммита (опционально) — что и зачем; не «как» (это видно из diff).

### 7.3 Pull Requests

- Описание PR содержит: ссылку на ID требования из спецификации, скриншоты UI-изменений, чек-лист тестов.
- Один PR = одна логическая единица.
- Squash merge.

### 7.4 Релизы и теги

- Semver: `vMAJOR.MINOR.PATCH`.
- Тег ставится при завершении каждого этапа (или раньше при значимом milestone):
  - `v0.1.0` — этап 1 готов и задокументирован
  - `v0.2.0` — этап 2 готов
  - `v0.3.0` — этап 3 готов
  - `v0.4.0` — этап 4 + экспорт
  - `v1.0.0` — все требования + тесты + защита диплома

### 8.2 Алгоритм расчёта сметы

1. Для каждой комнаты площадь = `tiles.length × 0.0625`.
2. Стяжка: `area × screed_*_per_m2`.
3. Электрика: длина всех маршрутов в метрах × `electrical_per_m`.
4. Штукатурка: суммарная площадь стен (длина × высота 2.7 м) × `plaster_per_m2`.
5. Потолок: `area × ceiling_*_per_m2`.
6. Покрытие пола: `area × floor_*_per_m2`.
7. Покрытие стен: для каждой стороны — `length × 2.7 × wall_*_per_m2`.
8. Мебель: для каждой расставленной единицы — `furniture[type]`.
9. Итог = сумма min, сумма max.

## 9. Дистрибуция (план для будущего, не для MVP)

- **MVP (v1.0):** один публичный домен, бесплатный для всех, для защиты ВКР.

3. **Интеграция с маркетплейсами** (клик по «Купить диван» → переход на партнёрский магазин).
4. **Совместное редактирование** (несколько устройств) — Supabase auth.
5. **Мобильная версия** — отдельная разработка.
6. **Раздельное покрытие сторон стен** (в рамках админки).
7. **Кастомные прайсы по `clientId`** через таблицу `pricing_overrides` в Supabase.

## 11. Глоссарий

| Термин                   | Значение                                                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Тайл                     | Единичная клетка сетки 0.25×0.25 м, базовая единица измерения.                                                         |
| Планировка (layout)      | Одна из типовых конфигураций дома.                                                                                     |
| Этап (stage)             | Один из 4 шагов взаимодействия пользователя.                                                                           |
| Маршрут (route)          | Путь электропровода от щитка/ответвления до точки.                                                                     |
| Точка (electrical point) | Розетка или выключатель на стене.                                                                                      |
| Сегмент стены            | Прямой участок стены между двумя пересечениями/углами.                                                                 |
| Чистовая отделка         | Финальная отделка: пол, стены, мебель.                                                                                 |
| Черновая отделка         | Стяжка, электрика, штукатурка, потолок.                                                                                |
| Коридор (corridor)       | Проходная зона, не учитывается в выборе покрытий и потолка.                                                            |
| Гардеробная (wardrobe)   | Маленькая зона хранения, не учитывается в выборе покрытий.                                                             |
| Веранда (veranda)        | Внешняя пристройка, отображается на 2D-схеме, в расчёты не входит.                                                     |
| Окно (window)            | Объект в стене, не блокирует электрику, уменьшает площадь штукатурки. **Введено в v1.5.0.**                            |
| Дверной проём (door)     | Разрыв в стене с дугой направления открытия в 2D, блокирует размещение мебели в проёме. **Введено в v1.5.0.**          |
| Группа сметы             | Объединение позиций по типу работы (например, «Стяжка пола» — все комнаты вместе). **Введено в v1.3.0.**               |
| Призрак (ghost)          | Полупрозрачная копия мебели, отображаемая под курсором при размещении/перемещении. **Введено в v1.4.0.**               |
| Секретный редактор       | Внутренний инструмент Таи для создания layout JSON-файлов, доступен по URL `/?editor=1&token=…`. **Введено в v1.6.0.** |

## Приложение A — Реализованные планировки (v1.0.0)

В `src/data/layouts/` лежат три JSON-файла, созданные на основе реальных планов от заказчика:

| ID  | Файл           | Сетка (тайлы) | Площадь (м²) | Состав                                                                                |
| --- | -------------- | ------------- | ------------ | ------------------------------------------------------------------------------------- |
| 1   | `layout1.json` | 36×32         | ~78          | 2 спальни, ванная, коридор, котельная, гостиная, кухня                                |
| 2   | `layout2.json` | 32×32         | ~64          | 2 спальни, 2 ванных, котельная, гардеробная, гостиная, кухня                          |
| 3   | `layout3.json` | 44×36         | ~99          | 3 спальни, 2 ванных, котельная, гардеробная, 2 коридора, кухня + гостиная (open plan) |

**Особенности:**

- В планировке 3 кухня и гостиная — **open plan** (без стены между ними), разделение условное по метражу.
- Все размеры комнат округлены до 0.25 м (1 тайл) с допуском ±0.5 м² от номинальной площади.
- Электрощиток во всех планировках расположен в котельной.
- Веранда отображается отдельным объектом за пределами основной сетки.
